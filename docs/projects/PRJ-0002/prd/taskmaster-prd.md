# Taskmaster（dsh-taskmaster）PRD

## 摘要

Taskmaster 是独立的 agent 任务调度引擎：把一组有依赖关系的任务注册成任务图，常驻引擎按依赖派活、盯活、验收、再派下一批，人只在确认闸与异常点出现。现在做的原因：派发靠记得调、顺序靠自觉、派出去是盲区、完成靠嘴说——这四件事已经在真实项目里反复咬人。做完后，属主注册一张图、开一次开关，剩下的进度、卡点、验收都可见可查。

## 发布公告

**标题**：Taskmaster——给 agent 工作流装上调度引擎
**副标题**：项目所有者把多步 agent 任务注册成图，引擎常驻推进，每一步有监控、有验收、有留痕
**客户问题**："我派出去的 agent 任务，顺序靠它们自觉、进度靠我记得去问、做完了说完了就完——图落了盘，执行断在半路。"
**如释重负的一句话**："注册完图我就没再管过：每批派发前我过一眼计划卡，卡住它会来叫我，做完它自己往下走。"

## 背景与问题

### 现状

今天多步 agent 工作的做法：人在会话里口头或文档里写明依赖顺序 → 逐个 spawn agent → 靠记忆逐个追问进度 → 执行者说"做完了"就当完成 → 手动启动下一步。一次 10 个任务的图，人要在会话里当调度器、监控器和验收员三个角色。

### 问题

| 问题 | 证据 | 影响 |
|---|---|---|
| 派发靠记得去调 | 工具是被动入口，不调不动 | 图落盘但执行断档 |
| 顺序靠自觉 | 依赖写在叙事里无强制 | 前驱未完后继开工，返工 |
| 派出去就是盲区 | 原话："取任务后对任务没有监控" | 卡住/死掉无人知晓 |
| 完成靠嘴说 | 执行者说"做完了"就信 | 不合格产物流向下游 |
| 调度绑死发起会话 | 会话一关调度断 | 长任务不可靠 |
| 只有正向链路 | 图无暂停/停止/注销 | 错图失控图无法收口 |
| 投递探活无寻址 | 引擎不知道任务绑在哪个会话 | 探活/打回/重挂没有落点 |

### 影响与证据

来源：2026-10-18 需求会话多轮收敛（原话见需求文档 v2.0「背景与来源」）+ 同日生命周期/拓扑/持久化二轮讨论。排重结论：DSH 自带 dsh-schedule 是定时提醒（按时间调度），与本引擎（按依赖调度）零重叠。不做的代价：每扩张一次 agent 工作流规模，人的调度负担线性增长，错序与漏验造成的返工不可计数。

## 目标与非目标

### 目标

- 注册任务图后**不做任何工具调用**，一个心跳节拍内引擎自动出计划卡（FR-8 证伪点）；
- 任何任务在全部前驱验收通过前**不存在被派发的可能**（派发拒绝日志可证伪）；
- 在途任务卡死**一个巡检周期内**被标记 stalled 并上报；
- 应用重启后：在途任务被重挂或如实标 stalled，**不重复、不跳步**；
- 异常路径下引擎**零自动 spawn**（红线，反向验证）。

### 非目标

- **不做拉模式认领**（R-14 延期）：一期推模式已够，拉模式的认领竞争与超时回收不在正确性关键路径；
- **不做网络面外部执行者**（R-15 延期）：一期是本地进程内 service，跨机器接入是二期事；
- **不做异常自动重跑/自修复**（R-16 永久拒绝）：写操作不幂等，自动重放可能造成不可逆业务写入；
- **不做执行者能力画像**：引擎不评估哪个 agent 擅长什么，执行者对引擎是匿名可替换劳动力；
- **不做多写者协同**：同一数据根只允许单写者引擎，多引擎协同的 leader 选举留二期。

## 用户旅程与流程设计

### 参与者与触发条件

- **参与者**：属主（人）、引擎（常驻）、执行者（agent，N 个执行者窗口）；
- **触发条件**：属主启用 `taskmaster.enabled` 并注册任务图；
- **前置状态**：引擎完成 Boot 五步自举（FR-15）；图通过校验（无环、判据齐全）；
- **结束状态**：图全部任务 done → 图休眠；或经人发起进入已停止/已注销；引擎可被停止，全部事实落盘可续调。

### 主流程（ASCII 图）

```text
注册图（校验：无环/写域/判据）
|
+-- 校验失败 --> 拒收 + issues（零落盘）
|
+-- 校验通过 --> 版本落盘 --> 图激活
     |
     v
[常驻心跳：每拍全量对账]
     |
     +-- 有交卷未验收 --> 核验 checks
     |     +-- 不过 --> 打回补证据（状态不变）
     |     +-- 过 --> 翻 done --> 关闭绑定 --> 级联解锁后继
     |
     +-- 在途探活 --> alive 继续
     |     +-- silent --> 主动探活一次
     |     +-- stalled/dead --> 上报落盘 --> 等人裁（绝不自动重跑）
     |
     +-- 就绪集有任务 --> 确认闸
     |     +-- 未确认 --> 出/更新计划卡等人
     |     +-- 已确认 --> 裁决+占位 --> 投递+建绑定 --> 执行者干活
     |
     +-- 就绪集空
           +-- 图未完 --> 报死锁等人裁
           +-- 图全 done --> 图休眠
```

### 状态与结果对照表

| 场景 | 触发 / 操作 | 系统结果 | 用户反馈 | 下一步 |
|---|---|---|---|---|
| 注册图 | tm_upsert | 版本快照落盘，图激活 | 回执 graphId+version | 等计划卡 |
| 确认派发 | confirm 计划卡 | CAS 占位→投递→建绑定 | 执行者窗口开工 | 等交卷/探活 |
| 驳回派发 | 不确认 | 零 spawn，任务保持 ready | 计划卡更新 | 人改图或确认 |
| 交卷过 | 执行者交卷+证据 | 翻 done，解锁后继 | 下一批计划卡 | 确认下一批 |
| 交卷不足 | 证据缺失 | 拒收打回，状态不变 | 执行者收到补充要求 | 补证据再交 |
| 卡死 | 活性信号中断 | 标 stalled 上报落盘 | 属主收到异常上报 | 人裁 |
| 暂停图 | 人发起暂停 | 不派新，在途照跑 | 视图标"暂停中" | 恢复或停止 |
| 停止图 | 人发起停止 | 在途转待处置，收口终态 | 视图标"停止中→已停止" | 查历史 |
| 注销图 | 人发起注销 | 移出活跃集，历史全留 | 视图可查不可恢复 | 无（不可逆） |
| 应用重启 | kill 后重启 | Boot 五步，在途重挂 | 重挂结果摘要 | 正常心跳 |

### 异常与恢复路径

- 投递失败 → 任务回就绪、占位回收、不自动重试、留痕可查；人可在下一批计划卡再确认；
- 事件丢失（完成回调未到达）→ 下一拍心跳全量对账兜底，照常推进；
- 执行者窗口死亡 → 进程存活信号翻 dead → 按留痕补验收，补不上报人裁；
- 属主窗口关闭 → 计划卡/上报落盘排队，重开补投，引擎照跑；
- 就绪集空但图未完 → 报死锁，引擎零动作，人改图或人裁；
- state.json 损坏 → 图快照 + 事件流重建（NFR-5）；
- 恢复入口全部在人：resume / reassign / reopen / 改图，重派必发新世代 runId。

- **涉及页面**：否
- **原型链接**：不适用：无新增或修改页面
- **覆盖范围**：不适用（agent 工具 + 文本交互）
- **原型版本 / 日期**：文本交互原型 v0.1 / 2026-10-18
- **访问说明**：本仓库内文档，所有人可读
- **覆盖状态**：默认 / 驳回 / 异常上报 / 打回

### 文本交互原型（无页面或工具交互时填写）

```text
【计划卡 · 待确认】（图 g-1001 v2 · 第 3 拍）
本批就绪：t-07「写用户接口」（等 t-03 done ✓）
写域冲突：无 ｜ 并发：1（S1 串行）
【输入】confirm / 驳回
【结果】confirm → CAS 占位 → 投递 t-07（runId r-8842）→ 绑定入台账
【下一步】等交卷或探活；驳回 → 任务回 ready，下一拍可再出卡
```

```text
【验收打回】（t-07 · runId r-8842）
交卷 checks 4 条：通过 3，缺证据 1（"接口联调通过"无留痕）
【结果】拒收，任务保持 running；打回通知经绑定 sessionId 送达执行者
【下一步】执行者补证据再交；状态不翻 done
```

```text
【异常上报】（t-09 · stalled）
信号：events seq 90 拍无增长 → silent → 主动探活无回应 → stalled
【结果】上报 + 落盘；引擎零自动动作
【下一步】人裁：resume / reassign / reopen / 改图（重派发新世代 runId）
```

### 需求明细

#### FR-1 任务图注册与版本

**优先级**：Must ｜ **角色**：属主 / 调用方插件 ｜ **依赖**：无

**描述**

引擎以注册的一张任务图为唯一调度依据；版本快照只增不删；在途执行按派发时快照跑完。调度语义是按依赖偏序推进，注册校验拒收有环图。

**验收标准**（Given / When / Then）

- AC-1.1 Given 一张合法 3 任务图，When 注册，Then tm_status 见 3 个 pending 且版本 v1 落盘。
- AC-1.2 Given 已注册图，When upsert 修正版，Then 旧版本可回读、在途任务不被中途换图。
- AC-1.3 Given 一张有环图，When 注册，Then 校验拒绝且零落盘。

#### FR-2 按依赖分发

**优先级**：Must ｜ **角色**：引擎 ｜ **依赖**：FR-1

**描述**

引擎只从"全部前驱 done"的任务中取活派发——无论触发来自工具、心跳对账还是重启续调。

**验收标准**（Given / When / Then）

- AC-2.1 Given 建表→接口→测试图且建表未验收，When 任何路径触发派发，Then 接口任务不在派发计划里（拒绝日志可证伪）。

#### FR-3 并行与写域裁决

**优先级**：Should ｜ **角色**：引擎 ｜ **依赖**：FR-2、FR-4

**描述**

同批就绪任务并行派发；写域重叠只放行先到者，冲突项进计划卡等人裁；并发上限可配。S1 并发上限固定为 1（串行派发）。

**验收标准**（Given / When / Then）

- AC-3.1 Given 同批 3 任务其中 2 个写域重叠，When 出计划卡，Then 放行 2 个、列出 1 个冲突。

#### FR-4 确认闸（计划卡）

**优先级**：Must ｜ **角色**：属主 ｜ **依赖**：FR-2

**描述**

派发前出计划卡：本批预览、写域冲突、并发数；人确认才真派，不带确认永不派发；gate=auto 切面内免确认。

**验收标准**（Given / When / Then）

- AC-4.1 Given 就绪集非空，When 不带 confirm 触发调度，Then 只产生计划卡，零 spawn。

#### FR-5 任务包视野最小化

**优先级**：Must ｜ **角色**：执行者 ｜ **依赖**：FR-10

**描述**

执行者初始上下文只含本任务投影：陈述、前置产出（大产物给路径+摘要）、验收判据、写域约束、回合预算。视野最小化由架构保证：任一执行者窗口同时刻只挂一条活跃绑定（FR-14、NFR-4）。

**验收标准**（Given / When / Then）

- AC-5.1 Given 任一执行会话，When 检查初始上下文，Then 不含非入边任务的信息。

#### FR-6 完成验收

**优先级**：Must ｜ **角色**：引擎 ｜ **依赖**：FR-10、FR-14

**描述**

交卷必须带 checks 逐条证据；引擎机械核验通过才 CAS 翻 done；不过打回补证据、状态不变；打回经绑定 sessionId 寻址。

**验收标准**（Given / When / Then）

- AC-6.1 Given 证据缺失的 complete，When 引擎核验，Then 拒收、任务保持 running、执行者收到补充要求。

#### FR-7 在途监控与探活

**优先级**：Must ｜ **角色**：引擎 ｜ **依赖**：FR-14

**描述**

每个 running 任务有三层活性信号（留痕心跳/回合预算/进程存活）；分级 alive → silent（主动探活一次）→ stalled（报人）；进程消失为 dead（按留痕补验收，补不上报人）。活性是投影，不进主状态机。

**验收标准**（Given / When / Then）

- AC-7.1 Given 一个 idle 不交卷的执行者，When 一个巡检周期过去，Then 被标 stalled 并上报。

#### FR-8 常驻对账循环

**优先级**：Must ｜ **角色**：引擎 ｜ **依赖**：FR-1、FR-15

**描述**

引擎按心跳节拍对活跃图全量对账（期望=图，实际=state.json+绑定台账），自主完成派发、催办、验收、图完成判定；事件只是即时加速，心跳是兜底。启动即交权：人只在确认闸与异常点出现。

**验收标准**（Given / When / Then）

- AC-8.1 Given 注册图后不做任何工具调用，When 一个心跳节拍过去，Then 自动出计划卡。
- AC-8.2 Given 一次完成事件被模拟丢失，When 下一拍心跳，Then 对账仍正确推进。

#### FR-9 量化视图

**优先级**：Should ｜ **角色**：管理层 / 属主 ｜ **依赖**：FR-1

**描述**

管理视图从图投影：kind/story/里程碑计数、波次、等待关系、燃尽点数；含图生命周期态与任务待处置态；无第二事实源。

**验收标准**（Given / When / Then）

- AC-9.1 Given 一张进行中图，When tm_status group_by=kind，Then 计数与图文件一致，未就绪项显示"在等谁"，暂停/注销图如实标注。

#### FR-10 任务投递

**优先级**：Must ｜ **角色**：引擎 → 执行者 ｜ **依赖**：FR-4、FR-14

**描述**

通道按可用性降级（startActivation / window branch / spawnTeammate / 纯对话流）；载荷含 runId 世代凭据与本任务投影；at-most-once；失败回滚不自动重试；每次投递尝试留痕；回话只认当前世代 runId；投递成功建绑定、终态关绑定。

**验收标准**（Given / When / Then）

- AC-10.1 Given 投递通道不可用，When 投递失败，Then 任务回就绪、无执行者残留、runs/ 有留痕、不自动重试。
- AC-10.2 Given 同一任务同世代并发触发，When 两次派发尝试，Then 最多一个在途 run。

#### FR-11 图级暂停与恢复

**优先级**：Must ｜ **角色**：属主 ｜ **依赖**：FR-8

**描述**

活跃图可暂停：不派新任务，在途照跑照验收照探活；恢复后下一拍正常续派。只改调度行为，不改图不改状态。

**验收标准**（Given / When / Then）

- AC-11.1 Given 活跃图存在就绪任务，When 暂停，Then 零新计划卡；在途交卷照常验收；恢复后一拍内正常出卡。

#### FR-12 图级停止

**优先级**：Must ｜ **角色**：属主 ｜ **依赖**：FR-8

**描述**

停止图：不派新 + 在途转待处置（不杀进程、可继续交卷验收但不解锁后继）；全部落袋后进"已停止"终态，可查不可恢复。

**验收标准**（Given / When / Then）

- AC-12.1 Given 有 2 个在途任务的图，When 停止，Then 零新派发；在途交卷照验收但后继不解锁；全部落袋后图=已停止。

#### FR-13 图级注销

**优先级**：Must ｜ **角色**：属主 ｜ **依赖**：FR-12

**描述**

注销图：移出活跃集，心跳跳过；在途绑定按失联处置报人（推荐先停止再注销）；版本/事件流/留痕全保留；不可逆。

**验收标准**（Given / When / Then）

- AC-13.1 Given 一张图，When 注销，Then 心跳不再对账它；tm_status 可查其历史；无恢复入口。

#### FR-14 在途绑定台账

**优先级**：Must ｜ **角色**：引擎 ｜ **依赖**：FR-10

**描述**

投递成功建立绑定记录：(graphId, 图版本, taskId, runId) 四元组唯一，另含 sessionId/通道/dispatchedAt/startedAt/lastEventSeq；是探活、打回、dead 判定、重启重挂的唯一寻址依据。基数：任务同时刻最多一条活跃绑定；同一 sessionId 不出现在两条活跃绑定中；终态关闭绑定，留痕永存。

**验收标准**（Given / When / Then）

- AC-14.1 Given 任一 running 任务，When 查台账，Then 有完整绑定记录；打回/探活经 sessionId 送达；done 后绑定关闭且留痕可查。
- AC-14.2 Given 人裁重派，When 新绑定建立，Then 新世代 runId 生效，旧世代回话被拒收。

#### FR-15 启动自举

**优先级**：Must ｜ **角色**：引擎 ｜ **依赖**：FR-8、NFR-5

**描述**

引擎无手动启动入口：宿主唤起 → enabled 开关 → Boot 五步：①加载配置 ②扫描图库校验元数据 ③快照+事件重建投影 ④按台账逐 run 处置（补验收/重订阅/标 stalled）⑤进心跳循环。

**验收标准**（Given / When / Then）

- AC-15.1 Given enabled=true 且有在途任务，When 应用重启，Then 无人介入完成 Boot 五步，在途被重挂或如实标 stalled，一拍内正常出计划卡。

#### FR-16 引擎级停止

**优先级**：Should ｜ **角色**：属主 ｜ **依赖**：FR-15

**描述**

停止整个引擎：心跳停、零派发零探活；在途不杀、台账保留；再启动按 Boot ④重挂。与开关的区别：禁用是配置态，停止是运行态。

**验收标准**（Given / When / Then）

- AC-16.1 Given 引擎停止期间，When 在途 agent 交卷，Then 落盘不丢；再启动后补验收正常续调。

## 非功能需求

| 编号 | 类别 | 要求 | 优先级 |
|---|---|---|---|
| NFR-1 | 安全约束 | 异常只报不修：stalled/dead/blocked/死锁唯一动作是上报+落盘；任何异常路径引擎零新 spawn；人裁重派必发新世代 runId | Must |
| NFR-2 | 可靠性 | 重启续调：就绪任务续派、在途按绑定台账重挂（补验收/重订阅/标 stalled），不重复、不跳步 | Must |
| NFR-3 | 安全阀 | taskmaster.enabled=false 时不派发不探活、读写照常；执行面不可用降级纯对话流 | Must |
| NFR-4 | 拓扑约束 | 属主窗口:图=1:1；执行者窗口:图=N:1；任何窗口同时刻只服务一张图；同数据根多写者红线 | Must |
| NFR-5 | 持久化纪律 | 图快照+事件流为唯一事实源；投影可重建；append-only+原子写+版本 CAS；一期无数据库 | Must |

## 边界与异常路径

- 空数据：无活跃图 → 引擎空转待命，视图显示空态，读写照常；
- 投递失败 → 回滚回就绪，不自动重试，留痕；
- 并发：同一任务同世代并发触发 → CAS 占位保证 at-most-once；
- 事件丢失 → 心跳对账兜底（AC-8.2）；
- 执行者窗口死亡 → dead 流程（补验收或报人）；
- 属主窗口关闭 → 待人事项落盘排队，重开补投；
- 死锁 → 上报，引擎零动作；
- state.json 损坏 → 快照+事件重建（NFR-5）；
- 同数据根第二个引擎实例 → 单写者锁拒绝启动；
- 有环图注册 → 校验拒绝（AC-1.3）。

## 常见问题

### 客户 FAQ

- **它替掉什么？** 人在会话里客串的调度器/监控器/验收员三个角色；口头或叙事文档里的依赖约定。
- **它不做什么？** 不自动重跑、不做执行者画像、不管 agent 怎么干活、不做跨机器调度（一期）。
- **对现有工作流有什么影响？** 零侵入：`taskmaster.enabled=false` 时完全不派发不探活，纯对话流照旧。

### 内部 FAQ

- **为什么是现在？** agent 工作流规模在涨，人的调度负担线性增长；宿主插件常驻形态有 goal-round-driver 先例。
- **为什么由我们做？** 需求方自己的项目（PRJ-0002 独立立项）；与 dsh-schedule 排重结论已白纸黑字。
- **最怕的问题是什么？** "常驻引擎出 bug 乱派发怎么办"——答案：确认闸在前（不带确认零 spawn）、S1 串行、任何异常只报不修、enabled 开关一键关停。
- **要砍先砍哪块？** 先砍 FR-16（引擎停止，可用禁用近似）与燃尽等视图增强；确认闸与验收是信任锚点，不可砍。

## 备选方案

- **纯工具形态（无常驻引擎）**：被否——FR-2/FR-7/NFR-2 全部退化为"靠人记得调"，回到原点；
- **复用 dsh-schedule 定时器实现**：被否——它是按时间调度，与按依赖调度语义不同，硬套会把依赖语义挤进 cron 缝隙；
- **接入外部调度器（Temporal 等）**：被否——引入外部服务与网络面，与"本地工具进程内 service"定位相悖，且确认闸/人裁语义要自己重新发明；
- **什么都不做**：被否——四个待解问题已在真实项目反复咬人。

## 发布与回滚

- **发布形态**：随 dsh-taskmaster 插件发行；`taskmaster.enabled` 默认 false，显式打开才生效；
- **灰度**：M1 仅需求方自用项目；M2 后视走查结论扩大；
- **回滚**：关开关即停（不派发不探活，读写照常）；图的暂停/停止/注销提供更细粒度收口；
- **可观测性**：事件流（append-only）为天然审计日志；计划卡/上报/驳回计数入结构化日志；
- **运维归属**：项目所有者自用；支持入口为本仓库 issue。
